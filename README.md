# App隐私整改核验

通报发布后，运营者需在十五个工作日内完成真实整改：隐私政策、权限弹窗、
实际采集与账号注销必须在同一客户端版本上同时生效。本项目提供一套可复测的
整改核验产品，覆盖登记、检测、审查、结论与报送监管的全过程。

## 数据流

```
登记（registry）        检测（detection）       审查（review）         结论（ledger）
渠道/版本/规则/权限  →  会话按发生时间解析   →  多人判断一致合并   →  只增不改的台账
采集字段/组件/注销      生效版本并逐条求值      重复提交去重分轮      报送结论可重建
```

1. **客户端版本登记**（`src/registry.py`）：App 与小程序按渠道登记版本、个人信息
   规则、权限用途、采集字段、第三方组件、注销路径与证据。灰度发布、商店审核
   延迟、小程序热更新都是带发生时间的发布事件，版本何时生效完全由事件决定，
   仅提交审核（`submitted`）不生效。
2. **隐私检测会话**（`src/detection.py`）：会话按发生时间解析当时生效的版本，
   对规则集逐条求值。求值是纯函数，同一输入重跑结果一致；每个违规都携带重现
   该问题的具体条件（场景、权限、拒绝行为、超期原因）。规则集（`src/rules.py`）
   以领域资料中的事实记录为来源，逐条可溯源、可版本化。
3. **审查与提交**（`src/review.py`）：多名审查员并发判断时，同一审查员取最新
   一次、不同审查员取最严格结论，合并结果与到达顺序和重复提交无关；运营方
   重复提交的材料按内容摘要去重，内容不同的提交按发生时间进入新一轮。
4. **整改结论台账**（`src/ledger.py`）：结论只增不改，轮次必须递增，早先的
   失败结论不会被后一次通过覆盖；结论通过链式摘要相连。报送监管的报告可由
   `rebuild_report` 从原始检测会话与审查判断完整重建。
5. **限期复核**（`src/deadlines.py`）：期限自通报发布次日起算十五个工作日，
   法定期限顺延按发生时间应用，发生在期限之后的顺延不生效。
6. **数据最小化**（`src/retention.py`）：检测求值只依赖白名单字段（权限名、
   字段名、步骤数、匿名化测试账号标识），原始报文、设备标识与真实账号在留存
   环节被移除；最小化后的会话仍能重建出同一份报送结论。

## 领域资料

`contracts/` 定义登记、规则集、检测会话、审查判断与提交材料的共享格式，
`fixtures/` 提供可公开使用的虚构样例：两条渠道（应用商店 App、微信小程序）、
两轮检测（首轮三项违规、复测全部通过）、一次期限顺延与多人并发审查。
样例不含真实个人信息、账号、密钥或连接凭据。

## 本地校验

```sh
python -m unittest discover -s tests -t .
```

测试覆盖：版本按发生时间生效（商店审核延迟/灰度/热更新）、十五个工作日与
顺延、规则溯源、三类违规的具体条件重现、检测可复测、并发审查一致合并、
重复提交去重、失败结论不被覆盖、报送结论从原始检测重建、数据最小化不破坏
可重建性。
